/**
 * =========================================
 * UNIVERSAL REVISION STRATEGY (BEST PRACTICE)
 * =========================================
 * Applies to: DSA, System Design, OS, DBMS,
 * CN, OOP, Languages, Tools
 */

/**
 * TRUTH
 * -----
 * Learning ≠ Revision
 * Learning → Depth
 * Revision → Speed + Recall
 */

/**
 * 🔁 3-LAYER REVISION MODEL (OPTIMAL)
 * ----------------------------------
 * Layer 1 (Recall)     → Fast
 * Layer 2 (Skeleton)   → Most Important
 * Layer 3 (Full Code)  → Rare
 */

/**
 * 1️⃣ LAYER 1: CONCEPT RECALL
 * --------------------------
 * Ask (without notes):
 * - What is it?
 * - Why does it exist?
 * - When should I use it?
 * - Trade-offs / Complexity?
 *
 * Time: 5–10 min/topic
 */

/**
 * 2️⃣ LAYER 2: SKELETON (DEFAULT MODE)
 * -----------------------------------
 * Write ONLY:
 * - Function / class structure
 * - Control flow
 * - Key conditions
 * - Important formulas / rules
 *
 * NO:
 * - Boilerplate
 * - Full syntax
 *
 * Time: 5–10 min/topic
 */

/**
 * 3️⃣ LAYER 3: FULL IMPLEMENTATION
 * -------------------------------
 * Do ONLY if:
 * - Logic is unclear
 * - You forgot edge cases
 * - You made same mistake twice
 * - Topic is high-frequency
 *
 * Time: 20–30 min (rare)
 */

/**
 * ⏱️ TIME RULE (VERY IMPORTANT)
 * -----------------------------
 * 70% Recall
 * 20% Skeleton
 * 10% Full Implementation
 *
 * Writing full code every revision = WASTE
 */

/**
 * 🎯 INTERVIEW RULE
 * ----------------
 * If you can explain it clearly,
 * you can code it under pressure.
 */

/**
 * 🧠 ACTIVE REVISION > PASSIVE
 * ----------------------------
 * Prefer:
 * - Explaining aloud
 * - Writing skeletons
 * - Dry runs
 *
 * Avoid:
 * - Re-reading theory
 * - Rewriting full code
 */

/**
 * 🛑 STOP REVISING WHEN
 * --------------------
 * - Recall is instant
 * - Explanation is fluent
 * - Errors are rare
 */

/**
 * FINAL TRUTH
 * -----------
 * Comfort comes from repetition.
 * Confidence comes from recall.
 * Speed comes from patterns.
 */
