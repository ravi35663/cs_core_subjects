# Automating recurring Claude Code work

## Why automate

Once you trust Claude with a task, stop running it by hand. A recurring prompt should run on its own trigger.

## The spectrum

| Option | Who runs it | You build | Use it for |
|---|---|---|---|
| **Routines** | Anthropic's cloud | Nothing (just a prompt, repo, connectors, trigger) | Default for repeat work |
| **Headless (`-p`)** | Your machine or CI | A script around it | Work that needs your environment or pipeline |
| **Agent SDK** | Your app | An app that calls `query` | Claude inside your product |

Start with routines. Move down the list only when the job needs more control.

## Routines

A routine bundles a **prompt**, a **repo**, **connectors**, and a **trigger**. It runs in the cloud, so no machine of yours has to stay on.

Triggers:
- **Cron schedule:** e.g. every morning at 9am
- **HTTP POST:** your own code starts a run
- **GitHub event:** e.g. a new pull request

Create one at `claude.ai/code/routines`, or from Claude Code:

```bash
/schedule daily dependency audit at 9am
```

Examples:
- Morning dependency audit
- PR triager on new pull requests
- Daily scan of Sentry errors, ranked by urgency

**Limits:**
- Routines are a research preview, so behavior may change.
- A schedule runs at most hourly.
- Each run starts from a fresh clone of the default branch and pushes only to `claude/` branches by default. This stops an unattended run from rewriting `main`.

## Headless mode (`-p`)

`-p` (`--print`) runs Claude Code once with no UI. It reads stdin, writes stdout, and pipes like any shell tool.

```bash
claude -p "summarize the changes in this diff"
```

`-p` skips auto-loading of hooks, skills, plugins, MCP servers, and CLAUDE.md. Startup is faster, but you must allow the tools you need explicitly.

### Structured output

Use a JSON schema to get data instead of prose. The result is in `structured_output`.

```bash
claude -p "Extract the exported function names from src/core/style.js" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}' \
  | jq '.structured_output.functions'
```

### Multi-step work with sessions

Save the session ID from one run and resume it later, with full context.

```bash
claude --resume "$(jq -r .session_id /tmp/plan.json)"
```

Use this when a first pass makes a plan and a second pass carries it out.

### Deterministic runs in CI

Use `--bare` when CI needs the same output on every run.

## Agent SDK

The Agent SDK embeds Claude Code in your own TypeScript or Python app. It exposes a `query` function with the same primitives as the CLI.

Pass a prompt and options, such as:
- `allowedTools`: what Claude may do
- a system prompt
- a permission mode

Then loop over the streamed messages and handle them in your app.

## Which to use

- **Routine:** repeat work, nothing to host.
- **`claude -p`:** the job feeds into your scripts or pipeline.
- **`--bare`:** CI must give identical results each run.
- **Agent SDK:** the work belongs inside your product.

## Important points

- Routines run in the cloud. Headless and the SDK run on your machine or your server.
- Routines push only to `claude/` branches unless you loosen that per repo.
- Use `-p` with explicit `--allowedTools` for unattended runs.
- Pair `--output-format json` with `--json-schema` when another script reads the result.
- Keep the run ID or session ID if you need to resume.
- Flag names can change. Check `claude --help` before you rely on them.
- This repo has no scheduled jobs yet. A good first candidate is a daily check of `02.dsa` with `node`.
